# OpenRemoteConnector MVP 与支持范围

> **历史参考，不作为实现依据。** 自 2026-10-18 起，以 [PRD v0.4](../PRD.md) 为当前产品需求。下文的无中继直连、设备各自提供 MCP、强制隔离等要求已被取代；保留原文用于追溯，不代表当前支持范围或技术决策。

原文更新日期：2026-10-15。历史状态：设计提案，尚未实现或完成兼容性验收。

当前用户故事、产品行为、支持范围与需求验收均见 [产品需求文档](../PRD.md)；以下为旧版范围与交付顺序。

OpenRemoteConnector 把个人设备上的指定能力授权给 Agent，核心是无中继直连、设备端执行权限、隔离执行以及可撤销的连接。安装目标为 Agent 侧一个 Skill、Linux 侧一条命令、macOS 后续一个 App。首版面向使用 Linux 工作站、家庭服务器或 VPS 的开发者，完成文件读取、隔离任务、审核修改的闭环。Linux 为 P0，macOS 为 P1；客户端优先级与设备系统独立，其他电脑上的 Agent 也可以访问 Linux 设备。

## 1 产品决策

| 维度 | MVP 决策 |
| --- | --- |
| 用户 | 单个设备所有者；可连接多个 Agent 客户端 |
| 设备 | 两台独立 Ubuntu 24.04 LTS x86_64 设备；受维护的 6.8 或更高内核，具体安全更新版本在 M0 固定；不泛称支持所有 Linux |
| 设备入口 | 一条命令进入安装及初始化；CLI + systemd 用户服务，无需桌面会话；所有者可经已有 SSH 管理 |
| 客户端 | Codex CLI 与 ChatGPT 自定义远程 MCP；其他客户端列入后续兼容队列 |
| 本地连接 | stdio 适配器直接连接设备服务，双方经过本地登记 |
| 远程连接 | Agent 直接连接终端上的 HTTPS；需要可达地址与端口，不使用任何自建或托管业务中继 |
| 文件 | 用户选择并审核导出的工作区；远程读取快照，修改以差异申请回写 |
| 命令 | Rootless Docker Engine 管理 OCI 容器，显式使用 gVisor runsc / systrap；不直接执行宿主 shell |
| 权限 | 客户端身份、设备、工作区、操作、期限组合授权；设备端强制检查 |
| Agent 安装 | 一个 Skill 提供指引、配置模板及必要辅助脚本；优先复用宿主 MCP，无额外常驻客户端；宿主限制时明确一次原生配置步骤 |
| 第三方 MCP | 首版只验证一个固定版本的文件类 provider，放进隔离环境；不承诺任意 Server 安全兼容 |
| 商业边界 | 不设置产品订阅调用额度；用户承担模型、主机、域名等成本；保留技术限流与资源配额 |

## 2 Agent 市场分类与优先级

这里的 Agent 指承载工具调用的产品或运行环境，而非 GPT、Claude、Gemini 等模型名称。表中覆盖当前常见的代表产品，不构成市场份额排名。优先级依据目标用户、接入成本和验收工作量制定。

P0 为 MVP 必须验收；P1 为 MVP 后优先扩展；P2 为需求驱动适配。官方支持 MCP 仅说明存在接入路径，不代表已经与 OpenRemoteConnector 实测兼容。

| 类别 | 代表产品 | 当前接入路径 | ORC 优先级与边界 |
| --- | --- | --- | --- |
| 本地编码 Agent | Codex CLI | stdio、Streamable HTTP，远程 OAuth | **P0**；本地与远程各一个测试路径；[官方文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) |
| 桌面和 IDE Agent | Codex 桌面端、IDE 扩展 | MCP 与插件接入；具体宿主配置不同 | **P1**；共享服务端，但单独验证配置发现、进程生命周期与安装流程；[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) |
| 云端通用 Agent | ChatGPT | 自定义远程 MCP，直接访问终端上公开可达的 HTTPS；不使用托管隧道 | **P0 直连兼容验证**；账户需有接入权限；保留宿主要求的原生连接设置，不承诺仅装 Skill 即可完成；[接入说明](https://developers.openai.com/plugins/build/app-quickstart) |
| 本地编码 Agent | Claude Code | 本地 stdio、远程 HTTP、OAuth，可随插件配置 | **P1 第一批**；优先验证同一套工具无需额外业务适配；[官方文档](https://code.claude.com/docs/en/mcp) |
| 通用桌面和云端 Agent | Claude Desktop、Claude 网页及 Cowork | 本地 connector 与远程 connector 是不同执行路径；远程连接由云端发起 | **P1**；本地 Desktop 与远程 OAuth 分别验收；[官方说明](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors) |
| IDE Agent | Cursor | MCP 配置，支持本地与远程连接 | **P1**；先提供配置模板，后验证完整流程；[官方文档](https://cursor.com/docs/mcp) |
| IDE Agent | GitHub Copilot 在 VS Code 中的 Agent | VS Code MCP server 配置 | **P1**；只承诺 VS Code 形态，不外推到所有 Copilot 产品；[官方文档](https://code.visualstudio.com/docs/agent-customization/mcp-servers) |
| 开源 CLI Agent | Gemini CLI | MCP server 配置，包括本地和远程服务 | **P1**；按选定发行版测试认证与输出限制；[官方文档](https://geminicli.com/docs/tools/mcp-server/) |
| 开源 CLI 和桌面 Agent | OpenCode | 本地、远程 MCP 与 OAuth | **P1**；固定主版本，配置格式不跨版本推定；[官方文档](https://opencode.ai/docs/en/mcp-servers/) |
| IDE 和 CLI 扩展 | Cline | stdio 与远程 HTTP/SSE | **P2**；先使用通用配置；[官方文档](https://docs.cline.bot/mcp/mcp-overview) |
| IDE Agent | Windsurf/Cascade 相关产品线 | MCP 配置；当前文档涉及 Devin Desktop，需按实际发行版识别 | **P2**；避免按旧品牌名假设相同配置路径；[官方文档](https://docs.windsurf.com/windsurf/cascade/mcp) |
| 自托管个人 Agent | OpenClaw | MCP 客户端注册与运行时消费路径；另有对外 MCP server 功能 | **P2**；先确认选定运行时如何消费外部工具，不能把 `mcp serve` 当作客户端集成；[官方文档](https://docs.openclaw.ai/cli/mcp) |
| 自建 Agent 和工作流 | 基于 SDK 的 Agent、Dify、n8n、LangGraph 等 | 按各运行时的 MCP 客户端或工具适配器集成 | **P2**；提供 SDK 级示例，不承诺这些平台的统一插件格式 |
| 移动 Agent 入口 | ChatGPT、Claude 的手机和平板客户端 | 通常通过对应云端连接访问远程设备 | **P1 体验验证**；手机是控制入口，不要求在手机运行 ORC Server；具体工具可用性按客户端验收 |

优先选择 Codex CLI，是因为配置和测试可重复；选择 ChatGPT，是为了验证云端到个人设备的真实需求。P0 不同时维护所有客户端原生插件。Claude Code 为 P1 首项，可作为第二家厂商的互操作性检查，避免设计绑定单一平台。

本地 Agent 常常已经拥有自己的终端和文件工具。ORC 只约束通过 ORC 执行的调用，不能收回 Agent 已有的本机权限。主要安全收益体现在云端访问个人设备、电脑 A 上的 Agent 访问 Linux 设备 B，以及被 ORC 管理的第三方 provider。客户端运行在 macOS 上不等于该 Mac 已成为 ORC 支持的受控设备。

## 3 终端设备范围

终端设备按“运行设备服务的位置”分类。Terminal.app、iTerm2、Windows Terminal 是终端模拟器，不是独立支持平台；首版不读取或接管用户既有交互式 shell 会话。

| 设备种类 | 常见系统和形态 | 优先级 | 支持边界与理由 |
| --- | --- | --- | --- |
| Linux 开发机和服务器 | Ubuntu 24.04 LTS x86_64 工作站、迷你主机、VPS | **P0** | rootless、user namespace、cgroup v2、systemd 与 runsc 通过探测；无桌面也可使用 |
| Apple Silicon Mac | MacBook、Mac mini、Mac Studio、iMac | **P1 第一批设备扩展** | Apple container 后端；macOS 26/27 分别验收，以签名、公证 App 安装和初始化，增加菜单栏与 Keychain 集成 |
| 其他 Linux | arm64、其他发行版和内核组合 | **P1 后续** | 复用接口，单独测试运行时、AppArmor/SELinux 与资源限制；不能从 x86_64 结果外推 |
| 较旧系统的 Apple Silicon Mac | macOS 14/15 等 | **P2 候选** | 评估 Lima 后端；未验证前不开放无隔离的兼容模式 |
| Windows PC 的 Linux 环境 | Windows 11 + WSL2 | **P2 候选** | 不按普通 Linux 自动支持；禁用宿主盘、Windows 互操作等旁路并单独验收 |
| Windows 原生设备 | PowerShell、Win32 应用、桌面自动化 | **P2** | 需要独立的权限、进程终止和隔离实现，不等同于支持 WSL2 |
| Intel Mac | x86_64 macOS | **P2** | Apple container 不覆盖；待需求验证后选替代后端 |
| NAS 和家庭服务器 | Synology、QNAP、自建 NAS | **P2** | 设备权限和内核差异大；容器部署不能自动获得整台 NAS 控制能力 |
| 树莓派和边缘设备 | Linux arm64、低内存环境 | **P2** | 复用 Linux 设计，但单独评估资源开销与内核功能 |
| Android 手机和平板 | Android、Termux 环境 | **P2 研究** | 不承诺整机控制、跨应用文件访问或后台常驻体验 |
| iPhone 和 iPad | iOS、iPadOS | **MVP 外** | 作为云端 Agent 的控制入口；不规划通用后台设备 Server |
| 浏览器扩展、IoT 和嵌入式设备 | 浏览器 profile、家居设备、专用硬件 | **MVP 外** | 后续通过单独适配器和权限模型扩展 |

P0 只在目标终端部署设备服务与随包认证模块，无独立网关或转发 VPS。服务是宿主上的用户服务，任务才进入 gVisor；不把设备服务嵌进特权容器。网络需从实际 Agent 执行环境到终端直接可达；同机、局域网、公网 IPv4/IPv6 或明确配置的 NAT 映射分别验证。无法直连的 CGNAT 环境明确失败，不回退到隧道、代理、TURN/DERP 或 VPN 中转。DNS、证书和发布服务不参与工具流量转发。

Linux 默认采用 Rootless Docker Engine + gVisor，选择不依赖 KVM 的 systrap 平台，以覆盖普通工作站和没有嵌套虚拟化能力的 VPS。此选择仍需 M0 验证完整组合；具体比较、前置条件与拒绝降级规则见 [Linux 沙箱设计](../LINUX_SANDBOX.md)。[gVisor 平台说明](https://gvisor.dev/docs/user_guide/platforms/)

macOS 第二阶段采用 Apple container 的轻量 Linux VM，不把 gVisor 当作 macOS 原生运行时。复用同一权限、快照与任务契约，但两个后端分别验收，不宣称隔离强度完全相同。[Apple container](https://github.com/apple/container)

## 4 MVP 用户流程

1. 用户用一条命令启动 Linux 安装器，由安装器核验发布包、安装固定依赖、配置专用运行时和用户服务并进入初始化。检查 rootless、runsc、user namespace、cgroup 与安全策略；必要管理员操作集中说明，常驻执行链不以宿主 root 运行。不要求用户手工部署多个服务；安装地址尚未发布。
2. 设备所有者通过本地 CLI 或自己的 SSH 会话选择项目目录，查看导出文件清单。默认排除凭证、版本控制元数据、ORC 配置以及链接和特殊文件；文件名过滤不能保证内容没有秘密，用户必须能审阅实际暴露范围。
3. 用户选择本机、局域网或公网直连；向导展示监听地址、证书、端口与设备身份。默认不开放远程访问；按需确认监听及网络设置。实际客户端验证可达后才显示已连接；配对不授予文件或命令权限。
4. Agent 安装一个 ORC Skill，由其指引宿主 MCP 注册或使用必要辅助脚本；宿主限制时保留一次原生配置步骤。Codex CLI 验证完整 Skill 流程；ChatGPT 验证直接远程 MCP 与设备认证。每台设备一个端点，两台设备分别连接。
5. 管理 CLI 显示经认证的客户端身份，用户授权指定工作区的读取和隔离运行能力，默认有效期一小时；工具 IPC 不具备管理审批权。
6. Agent 读取快照、在独立 Linux 环境执行任务、获取有限输出；可以提交修改申请。
7. 管理 CLI 展示经过控制字符转义的文件差异，用户确认具体请求摘要后由文件代理校验原文件版本并回写。Agent 不能通过 MCP 代替设备所有者批准自己的修改。
8. 用户暂停或撤销授权。新调用立即拒绝，正在运行的隔离实例进入终止流程；界面显示实际终止结果。

没有人在设备旁时，可以使用预先授予的有限读取和隔离运行权限；需要确认的回写保持待处理并最终超时，不会因为等待时间较长自动通过。

Linux 端默认行为：退出管理 CLI 不停止服务；“暂停访问”阻止新调用并终止关联任务；“停止服务”关闭连接并清理 ORC 管理的隔离实例。开机运行和用户 lingering 需用户明确启用；未启用时不承诺登出后继续服务。每个任务禁止容器自动重启，监督器崩溃由独立 watchdog 清理，恢复服务先对账再接单。睡眠、断网或重启都不能触发任务自动重跑。

macOS P1 通过签名、公证 App 安装并进入向导，管理必要后端资源，提供菜单栏、登录启动与睡眠恢复体验；关闭窗口与真正退出的行为单独定义和验收，不阻塞 Linux MVP。

## 5 首版能力与明确排除项

| 首版能力 | 完成标准 |
| --- | --- |
| 设备身份 | 固定 device ID 与密钥；设备名称可改，但不能改变路由目标 |
| 工作区读取 | 只读取授权快照；返回快照版本，拒绝任意宿主绝对路径 |
| 隔离执行 | 固定工具链镜像、默认任务无网络、限制 CPU/内存/磁盘/时间；无宿主凭证 |
| 修改申请 | 展示差异、绑定内容摘要、本地确认、冲突检测；不能静默覆盖本地修改 |
| 授权管理 | 分客户端、设备、工作区、操作和时限授权；可撤销；拒绝默认开放权限 |
| 多设备 | 两台独立 Linux 设备分别授权，覆盖工作站与 VPS；离线不切换目标；连接恢复不重放修改操作 |
| 第三方 MCP | 一个固定版本 provider 在隔离环境中通过；明确 tools 子集和内容限制 |
| 本地可观测性 | 谁、何时、在哪台设备、调用何能力、是否被拒绝；默认不记录完整文件正文和 token |
| 无中继直连 | TLS 与认证运行在终端；无官方账号、独立网关、反向隧道或其他业务中继；不可达时明确失败 |
| 安装体验 | Linux 单命令安装并初始化、Agent 单 Skill 入口；所需原生配置与网络前提明确；支持幂等重试、升级和卸载 |

MVP 不提供任意宿主 shell、sudo、原生 Xcode 构建、浏览器已登录 profile 控制、屏幕录制、键鼠控制、全盘访问、跨用户团队管理、公开插件市场、任意 MCP 自动安装、全协议透明代理或任何业务中继。直连 TLS 不代表返回给 Agent 的内容对模型提供方保密。

任务镜像预装有限工具链，适合离线文件处理与已有依赖的测试。任意项目现场下载依赖、访问私有包仓库、使用 GPU、签名证书等属于后续能力，不能为了跑通演示而直接挂载宿主 home 或导入所有环境变量。

## 6 实施顺序与验收

以下按交付依赖排序，不把缺乏实现数据的工期估算当作承诺。

| 阶段 | 输出 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 可行性验证 | rootless/runsc 实验、设备内认证选型、真实客户端直连、Skill 配置路径与固定版本清单 | 无 KVM VPS 可运行；设备认证与直连通过；无中继；隔离、资源限制和跨设备拒绝通过 |
| M1 本地纵向切片 | CLI、设备服务、文件快照、任务生命周期、授权模型 | 不用 GUI 也能完整验证授权、执行、撤销与结果权限 |
| M2 无中继远程访问 | 设备内 HTTPS/认证、连接向导、两台 Linux 设备 | 局域网与公网直连、TLS/设备身份、断线恢复通过；不可达 CGNAT 不回退中继 |
| M3 Linux 产品体验 | 单命令安装与升级卸载、单 Skill 接入、CLI 授权审批、用户服务与诊断 | 非作者用户不手工搭服务即可初始化；额外网络/宿主配置可理解；登出、停止及崩溃清理通过 |
| M4 试用发布 | 固定版本发布包、兼容记录、安全回归集、试用反馈 | P0 组合全部通过；再决定 P1 的开发顺序 |
| M5 macOS 扩展 | Apple container 后端、签名公证 App 安装向导、Keychain、菜单栏 | 通过共同安全契约及 macOS 专项检查；Linux 与 Mac 混合设备访问通过 |

必须覆盖的验收场景：

- 两台独立 Linux 主机，至少一台真实工作站及一台跨网络 VPS，VPS 不要求暴露 `/dev/kvm`；同机双进程或仅 Docker Desktop 测试不能替代这项。
- 核验 rootless 引擎与真实 runsc 配置；缺少 user namespace、cgroup v2 或必要控制器时拒绝启动；不自动修改整机安全策略。
- 内存、CPU、进程与线程、临时存储、日志洪泛和墙钟超时分别有压力测试；参数被接受不代表限制生效。
- Codex CLI 本地、Codex CLI 远程、ChatGPT 远程三条路径分别完成读取、任务、修改申请和撤销。
- 错误 issuer、audience、客户端、设备、工作区、过期授权、已撤销授权均拒绝；仅改变设备名称不影响授权。
- `../`、符号链接、硬链接、大小写与 Unicode 路径变体、文件替换竞争、特殊文件均不能越过工作区边界。
- 构造恶意脚本尝试读取宿主测试凭证、访问本地服务、联网、启动逃逸子进程、写爆磁盘；只使用人工测试秘密。
- 重复请求、超时、服务重启、设备休眠、两个 Agent 并发写入，不产生静默重复操作或错误设备执行。
- 撤销时阻止新操作，终止已有任务；如果终止失败，界面明确显示而非误报完成。
- 杀死设备服务、断开管理 SSH、停止引擎及重启宿主后，不留下无限运行的孤儿任务，不终止用户无关容器。
- 设备连接日志不含 Authorization、请求正文或工具结果；诊断包不包含凭证或文件内容。
- 从实际 Agent 执行环境验证直达设备的流量路径；禁用全部中继仍可完成受支持的调用，不可达环境不偷偷改用代理。
- 干净 Linux 单命令安装、重复安装、签名失败、升级和卸载分别验证；单 Skill 接入记录实际手动步骤，不能把多次配置宣传为零配置。

建议试用目标：5–10 位目标用户、两周真实使用；分别记录设备安装、Skill 接入与直连配置时间、首次调用成功率、重复使用情况，以及因隔离边界无法完成的任务。只有连接量或 GitHub stars 不足以证明产品价值。

## 7 发布标注

兼容记录至少包含客户端名称和版本、系统版本、认证方式、传输方式、读写与撤销测试结果、测试日期。P1/P2 客户端可以自行尝试，但只有通过记录的组合才标记为正式支持。

任何无法建立隔离、验证身份或强制资源限制的环境都应停止执行并解释原因，不自动回退为 runc、普通 rootless 容器、bubblewrap 或宿主命令。Linux P0 不承诺任意系统调用、GPU、eBPF、内核模块或 Docker-in-Docker；macOS P1 不承诺原生 Xcode 与桌面操作。扩展能力必须有独立后端与验收依据。
